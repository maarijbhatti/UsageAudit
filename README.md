# UsageAudit

Independent usage-based billing verification for finance and engineering teams. This repository implements a local, multi-tenant MVP with real PostgreSQL persistence, NestJS APIs, a BullMQ worker, and a Next.js dashboard.

## Run locally

Prerequisites: Node.js 24 LTS, pnpm 12.18.0, Docker with Linux containers. The tested Node version is 24.14.1. Install pnpm with `npm install -g pnpm@12.18.0` if needed.

```bash
pnpm install --frozen-lockfile
pnpm setup
docker compose --env-file .env -f infrastructure/compose.yaml up -d --build --wait
pnpm db:migrate
pnpm db:seed
pnpm dev
```

Open [the application](http://localhost:3000), [API health](http://localhost:4000/api/v1/health), or [Swagger](http://localhost:4000/api/docs). The worker starts with `pnpm dev`. Backend source changes require restarting that command; Next.js refreshes frontend edits automatically.

`pnpm setup` generates random local database, object-storage, and encryption credentials in ignored `.env`. Keep that file: rotating its encryption key without re-encrypting stored Stripe secrets makes existing connections unreadable.

MinIO's upstream community container images are no longer available. Compose builds the pinned official `RELEASE.2025-10-15T17-29-55Z` source release. The first build downloads Go dependencies and takes several minutes. MinIO is used here for local development; use maintained S3-compatible storage for deployment. The local services bind only to loopback: PostgreSQL 5438, Redis 6388, MinIO S3 9008, MinIO console 9009.

## Complete an audit

1. Register and create an organization, or sign in with a demo account.
2. In **Imports**, upload `fixtures/valid-usage.csv` as application usage, preview/map the columns, and confirm.
3. In **Customers**, map source `acme` to provider `cus_acme`. In **Metrics & pricing**, map `requests` to `meter_requests` using `SUM`.
4. Under **Pricing versions**, set `requests`, provider price `price_requests`, `FLAT_PER_UNIT`, `USD`, rate `0.02`, effective from `2026-10-01T00:00:00Z`. Demo accounts already have this configuration.
5. Upload `fixtures/billing-usage.csv` as provider summaries and `fixtures/invoice-lines.csv` as invoice lines. Create a provider snapshot from those two completed imports.
6. In **Reconciliations**, select October's explicit interval `[2026-10-01, 2026-11-01)`, the source import, and provider snapshot. Check readiness and start the audit.
7. Open a finding, inspect its frozen evidence, change it to **INVESTIGATING**, and add a comment.
8. Generate a CSV from the run detail and download it in **Audit reports**.

For the exact 100,000-event success scenario, run `pnpm fixtures:large` and upload `fixtures/generated/usage-100000.csv` in a fresh organization. The Acme provider fixture has 92,000 units and a 184,000-cent invoice line. The engine derives $2,000 expected, $1,840 actual, and $160 potential underbilling. Additional provider customers require their own mappings or are reported as uncovered evidence. Reimporting the same logical events never increases organization usage.

## Quality checks

```bash
pnpm lint
pnpm typecheck
pnpm test
pnpm build
pnpm test:integration
pnpm exec playwright install chromium
pnpm test:e2e
pnpm test:layout
pnpm audit --prod
```

Integration tests create/use only databases ending in `_test`, including `usageaudit_migration_test` for migration rollback/reapply checks. They require the Compose services and permission to create test databases. `TEST_DATABASE_URL` is generated by setup. Browser tests use ports 3100/4100 and the test database; build first. The API integration scenario imports **100,000 distinct events twice** and tests persistence, idempotency, evidence, authorization, review history, reports, and bounded job failure. The browser workflow covers the UI with a compact equivalent CSV.

`pnpm test:layout` uses port 3200 and test-only intercepted responses to check mobile table scrolling without database services. It does not replace the real API browser workflow. Current verification results and blockers are recorded in [implementation status](docs/implementation-status.md).

## Repository

- `apps/web`: Next.js App Router, Tailwind, shadcn-style source components, React Hook Form/Zod, TanStack Query.
- `apps/api`: NestJS 12, Argon2id sessions, RBAC, TypeORM migrations, domain services and OpenAPI.
- `apps/worker`: BullMQ processors, database outbox dispatcher, daily pinned-evidence schedules.
- `packages/billing-core`: framework-independent decimal calculation and evidence classification.
- `packages/provider-adapters`: CSV validation/export, fixture adapter, official read-only Stripe SDK adapter.
- `packages/shared-types`, `packages/config`: reusable contracts and validated configuration.

## MVP boundaries

Live Stripe has not been verified with credentials. Only flat per-unit pricing and nonnegative integer usage are supported. USD, EUR, GBP, CAD, AUD, JPY, KWD, and BHD have explicit rounding policies. Unsupported tiers, transformed quantities, inclusive taxes, discounts, credits, and prorations are surfaced instead of silently calculated. Price versions must have non-overlapping explicit periods; existing rates are not edited in place.

Schedules rerun a fixed period with pinned imports/snapshots daily in UTC; they do not automatically discover the next invoice period or synchronize new evidence. Members must register before an owner/admin adds them; email delivery, password reset, MFA, and SSO are not implemented. Organization closure revokes access and connections while preserving audit evidence. No payment, invoice modification, refunds, or tax calculation is performed.

This is a production-oriented foundation, not a claim of audited compliance or production certification. Deployment-specific secrets management, backups, retention policy, monitoring, TLS, and least-privilege service roles remain operator responsibilities.
